## 页面结构重构：登录页 + 双 tab 首页

需求：index.vue 改为登录页 → 登录后跳首页；首页底部两个导航（导航1 / 导航2）。

最终结构（`pages/index`、`pages/mine` 已删除）：
- `pages/login/login.vue` —— 登录页，放在 `pages` 数组**首位**作为启动页。用户名 + 密码，`v-model` 双向绑定，演示账号 **admin / 123456**，成功后 `uni.setStorageSync('token')` 并 `uni.switchTab` 跳首页；`onLoad` 中若已有 token 则自动跳首页。
- `pages/home/home.vue` —— tabBar 第一项「导航1」，显示登录用户名，提供退出登录（`uni.reLaunch` 回登录页）。
- `pages/nav2/nav2.vue` —— tabBar 第二项「导航2」。

**关键踩坑点（重要）**：
1. **tabBar 页面必须用 `uni.switchTab()` 跳转**，用 `uni.navigateTo()` 会直接失败。
2. 非 tabBar 页面（登录页）跳转回登录页要用 `uni.reLaunch()`，否则页面栈残留。
3. 登录页必须放在 `pages` 数组**第一位**才是启动页；tabBar 里的页面不能放首位。
4. 本项目 `pages.json`/`tabBar` 是编译期配置，改完必须重新编译。
5. 图标用单张 `static/logo.png` 双端占位，App/小程序端建议换成 81×81 PNG（普通态+选中态两张）。

## 2026-10-16 补充：语法坑 + 触底加载

**修复 `home.vue` 报错**：`methods` 里方法之间误用分号 `;` 分隔（应为逗号 `,`），导致整个 `methods` 对象解析失败、`goyewuone` 未定义。**规则：`methods`/`data`/`computed` 是对象，成员之间用逗号，最后一个不加；分号只用于函数体内部的语句。**

**`pages/yewu/yewuone.vue` 重写为触底加载 Demo**：
- 重要：**uni-app 不支持 `<h1>` 等 HTML 标签**（小程序/App 端不渲染），`<text>` 内只能嵌 `<text>`。标题要用 `<view>` + 样式模拟。
- 上滑加载核心钩子是页面级 **`onReachBottom()`**，配合 `pages.json` 里的 **`onReachBottomDistance`** 控制提前触发距离。
- 实现要点：`page`/`pageSize`/`status`/`isLoading` 四件套防重复请求；`mockRequest` 模拟分页接口，共 15 条分 3 页；底部三态提示（可加载/加载中/没有更多）。

**项目页面结构现状**：`pages/login/login`（启动页）、`pages/home/home`（tab 首页，含业务1~4 按钮）、`pages/yewu/nav2`（tab「我的」）、`pages/yewu/yewuone`（业务1，二级页用 navigateTo 进入）。

**`yewuone.vue` 增加下拉刷新**（与触底加载配套，构成完整列表页）：
- `pages.json` 该页 style 需加 **`enablePullDownRefresh: true`**（默认关闭，不加钩子不触发），另配 `backgroundTextStyle: "dark"`、`backgroundColor: "#f5f7fa"`。
- 页面顶层写 **`onPullDownRefresh()`**（与 `onLoad`/`onReachBottom` 平级，**不能写进 methods**）。
- **关键坑：必须手动调 `uni.stopPullDownRefresh()`**，否则转圈不会停。本实现是在数据加载完成回调里停止（比 setTimeout 猜时间更准）。
- `loadData(isRefresh)` 用参数复用同一套逻辑：下拉刷新时先重置 `page=1 / list=[] / status='more'` 再加载，完成后 `stopPullDownRefresh` + toast「刷新成功」。
- 注意 `isLoading` 为 true 时收到下拉也要停动画，否则卡死。

**`pages/yewu/nav2.vue`（tab「我的」）重写为个人信息维护表单**：
- 字段：账号（只读展示，取 `uni.getStorageSync('username')`）、姓名（text input）、年龄（**`type="number"`**）、专业（**`<picker mode="selector">` 下拉**，选项 专业1/专业2）、保存按钮。
- 下拉选择器要点：`picker` 用 `:range="majorList"` + `:value="majorIndex"`，`@change` 里 `e.detail.value` 是**下标（字符串，需 Number 转换）**，再映射回文字存进 `form.major`。
- 保存逻辑：姓名非空、年龄用正则 `/^\d+$/` + 范围（1~150）校验、专业必选；保存时年龄 `Number()` 转数字类型；演示存 `uni.setStorageSync('userProfile')`，真实项目换 `uni.request`。
- `onShow` 里回填已存资料，并同步下拉的 `majorIndex`。

**修复「上滑加载更多」在真机不触发的问题**（根因已定位）：
- 原因：`onReachBottom` 的触发前提是**页面本身可滚动**。首屏 5 条数据未撑满屏幕时页面无滚动条，永远滚不到底部，钩子不触发。**不是代码写错。**
- 验证方法：临时把 `pageSize` 改大（如 20），若能触发即确认是数据量问题。
- 解决方案（已实现）：`loadData()` 改为返回 **Promise**；新增 `checkFillScreen()`，用 `uni.createSelectorQuery().in(this)` 取 `.page` 高度，对比 `uni.getSystemInfoSync().windowHeight`；内容不足一屏则递归加载下一页，直到撑满或 `status === 'noMore'`。
- 新增 `autoFilling` 标志，自动补足期间忽略 `onReachBottom`，避免与用户触底重复请求。
- 其它备选方案：底部加撑高占位元素（治标不治本）；数据量少时直接显示「没有更多了」。
- 演示数据调整为 `pageSize: 8`、`total: 30`（4 页），便于观察上滑加载效果。

**新增 `pages/yewu/yewutwo.vue`（业务2）—— 左右滑动的 tab 切换页**：
- 结构：顶部自定义 tab 栏 + 下方 **`<swiper>` 实现左右滑动切换**，每个 swiper-item 内套 `<scroll-view scroll-y>` 承载内容（因为 swiper 有固定高度，内部必须用 scroll-view 才能各自滚动）。
- **双向联动**：点顶部 tab → 修改 `current`，swiper 自动滑过去；手指滑 swiper → `@change` 里 `e.detail.current` 同步回 `current` 高亮。这是 tab+swiper 的核心。
- 布局关键：`.page` 用 `height:100vh` + `flex-direction: column`，`.swiper` 用 `flex: 1` 占满剩余高度。
- `home.vue` 业务2 按钮已去掉 `loading` 属性，改为 `@click="goyewutwo"` 跳转；新增 `goyewutwo()` 方法（`uni.navigateTo`）。

**注意**：用户已自行改动 `pages.json`/`media`：登录页 `navigationStyle: custom`；tabBar 换成 `static/img/` 下的 main/mainHL/me/meHL 图标；导航栏配色改为 `#dd524d`（红）配白字。改动前需先 Read 最新内容。

**新增详情页 + 列表传参（`pages/yewu/detail.vue`）**：
- 列表项 `@click="goDetail(item)"`，跳转用 **`uni.navigateTo({ url: '/pages/yewu/detail?id=xx&title=yy' })`**；含中文的参数必须 `encodeURIComponent` 编码，详情页用 `decodeURIComponent` 还原。
- 详情页在 **`onLoad(options)`** 中接收参数（options 即 url 中 `?` 后的对象），并做了三件事：接收展示、`uni.setNavigationBarTitle` 动态改标题、`uni.navigateBack()` 返回。
- mock 数据已加 `id` 字段（= 序号 no）用于传参。
- 补充：另一套传参方式是 `uni.navigateTo` 的 `success` 里通过 `eventChannel` 通信（`events` 参数），适合传对象/大数据的场景，简单数据用 url 拼接即可。

**已改用 EventChannel 传参（第三种方式，替代 URL 拼接）**：
- 列表页 `goDetail(item)`：`uni.navigateTo({ url: '/pages/yewu/detail', events: { refreshList: () => this.refresh() }, success: (res) => res.eventChannel.emit('sendData', { data: item }) })` —— URL 不再拼任何参数。
- 详情页 `onLoad`：`this.channel = this.getOpenerEventChannel()`，再 `channel.on('sendData', res => ...)` 接收**完整对象**（无需 encode/decode，无长度限制）。
- 反向回传已打通：详情页 `channel.emit('refreshList')` + `uni.navigateBack()`，列表页通过 `events.refreshList` 收到后调 `refresh()` —— 实现「详情页操作后自动刷新列表」闭环。
- 关键点：**EventChannel 仅 `navigateTo` 支持**；`redirectTo`/`switchTab`/`reLaunch` 都不支持。`getOpenerEventChannel()` 只能在被 `navigateTo` 打开的页面里调用。
